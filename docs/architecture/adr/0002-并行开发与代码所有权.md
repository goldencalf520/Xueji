# ADR 0002：多 agent 并行开发的代码所有权与冲突规避

- 状态：已采纳（2026-10-11）

## 背景

全部实现拆成 GitHub issue，由多个 agent 同时认领。冲突主要来自"人人都要改的集中文件"：
路由表、模块注册、页面清单、Prisma schema、环境变量、共享类型的 barrel 文件。

## 决定

1. **每个 issue 声明「独占路径」**，只允许修改这些路径；其它路径只读。路径按"功能目录"划分，一个目录只属于一个 issue。
2. **消灭集中注册文件**，改为预注册或自动发现：

| 原冲突点 | 处理方式 |
|---|---|
| NestJS `app.module.ts` | 58 个功能模块已在 `apps/server/src/modules/index.ts` **预注册为占位模块**，实现时只改模块自己的目录 |
| `common.module.ts` | 鉴权、权限、审计、加密、接口防护、队列、可观测性 7 个基础设施子模块已在 `CommonModule` **预注册为占位**，各基础设施 issue 只改 `common/<子目录>/` |
| 包依赖（package.json / pnpm-lock.yaml） | 可以在自己负责的包里**新增**依赖（精确版本）；lock 文件冲突时 rebase 后重新 `pnpm install` 生成，不要手工合并 |
| 小程序 `pages.json` | 43 个页面（P-01～P-43）**已全部注册并有占位页**，实现时只替换对应 `.vue` |
| 管理端 / 医院端 / 移动端路由 | `import.meta.glob` **自动收集** `src/modules/*/{admin,hospital,mobile}.routes.ts`，菜单由路由 meta 生成 |
| 客户详情页的标签页 | 详情页自动收集 `src/modules/*/customer-tabs.ts`（由客户详情 issue 建立机制） |
| Prisma 单文件 schema | **多文件 schema**：每个域一个 `.prisma` 文件，且**不允许跨文件 relation**（见 ADR 0003） |
| 共享类型 barrel | `@xueji/shared` 用子路径导出，每个域一个契约文件 `src/contracts/<域>.ts`，**不在 index.ts 汇总** |
| 规则引擎、AI 网关 | 按子目录拆（`rules/src/scoring/`、`ai/src/prompts/`…），各自子路径导出 |
| 种子数据 | `prisma/seed/*.seed.ts` 自动按文件名执行，每个域一个文件 |
| 环境变量 | 规划中的变量已全部登记在 `.env.example`；各模块自己校验自己的变量 |
| 模块间调用 | 优先用领域事件（`@nestjs/event-emitter`，事件名 `<域>.<事件>`，事件类型定义在发布方模块的 `events.ts`）；需要同步调用时 import 对方导出的 Service |

3. **只追加文件**（append-only）：确需修改时只能在末尾追加，合并冲突时保留双方：
   `apps/server/src/modules/index.ts`、`.env.example`、`apps/miniapp/src/pages.json`（只在对应分包末尾追加）、
   `packages/shared/src/core/enums.ts`（只追加取值）。
4. **同一目录的多个 issue 串行**：例如 `modules/mirror/` 的基础版、风险分类、记忆三个 issue 以 "Blocked by" 串起来，不会同时开工。
5. **契约先行**：后端 issue 先合并 `packages/shared/src/contracts/<域>.ts`（可单独开一个小 PR），前端 issue 依赖契约而不是依赖后端实现细节。
6. 依赖关系写在 issue 的「依赖」一节（`Blocked by #n`），并用 `wave:N` 标签标出可并行的批次：同一 wave 内的 issue 互不依赖、路径不重叠，可以同时开工。

## 后果

- 新增功能几乎不需要触碰别人的文件；剩余的少量冲突都发生在只追加文件里，解决方式固定。
- 代价：放弃 Prisma 跨域 `include`，跨域查询在服务层拼装（见 ADR 0003）。
