# ADR 0003：数据库 schema 组织与迁移协议

- 状态：已采纳（2026-10-11）
- 依据：产品文档 §11（数据设计）

## 决定

### 1. 多文件 schema，一个域一个文件

`apps/server/prisma/schema/` 下：`_base.prisma`（generator + datasource，架构维护）+ 每个域一个文件，
文件名与表的归属见 `apps/server/src/modules/<模块>/<模块>.module.ts` 顶部注释和 `docs/architecture/ownership.md`。

### 2. 不使用跨文件 relation（无数据库外键）

Prisma 的 relation 需要在**两个模型上都声明字段**，跨域 relation 会让两个 issue 同时修改同一个文件。因此：

- 跨域引用只用**标量外键字段 + 索引**，如 `customerId BigInt @map("customer_id")` + `@@index([customerId])`；
- 同一文件内的父子表（如 `h_assessment` ↔ `h_assessment_answer`、`h_referral` ↔ `h_referral_return`）可以声明 relation；
- 数据库层不建外键约束，引用完整性由服务层保证（与阿里巴巴 Java 开发手册"外键与级联在应用层解决"一致）；
- 跨域查询在服务层拼装（先查主表，再按 ID 批量查关联表），禁止在业务代码里写跨域 JOIN 的原生 SQL（统计聚合除外）。

### 3. 字段与命名约定（对应 §11.1）

| 项目 | 约定 |
|---|---|
| 模型名 / 字段名 | PascalCase 模型 + camelCase 字段，`@@map("snake_case")` / `@map("snake_case")` 映射到文档中的表名、字段名 |
| 健康类表 | 表名以 `h_` 开头（模型名以 `H` 开头，如 `HAssessment`） |
| 主键 | `id BigInt @id @default(autoincrement()) @db.UnsignedBigInt`；对外展示用业务编号（`customer_no` 等） |
| 时间 | `DateTime @db.DateTime(3)`；`createdAt @default(now())`、`updatedAt @updatedAt`；软删除 `deletedAt DateTime?` |
| 审计字段 | `createdBy String? @db.VarChar(32)`、`updatedBy`（员工 ID 或 `system`） |
| 金额 | `Decimal @db.Decimal(12, 2)` |
| 枚举 | `String @db.VarChar(32)`，取值来自 `@xueji/shared` 的词汇表（不用 Prisma enum，便于追加取值） |
| 配置类 | `Json` |
| 加密字段 | 名称以 `Enc` 结尾（列 `*_enc`），`Bytes @db.VarBinary(N)`，由 Prisma 扩展自动加解密 |
| 查找哈希 | 名称以 `Hash` 结尾（列 `*_hash`），`String @db.Char(64)`，HMAC-SHA256 |
| 索引 | 按 §11.6 建立；唯一约束用 `@@unique` |

### 4. 迁移协议

1. 只在自己的 issue 分支里修改自己域的 `.prisma` 文件；
2. 生成迁移：`pnpm db:migrate --name <issue号>_<简述>`（如 `12_consent`），迁移只包含本 issue 的表；
3. **合并前 rebase 到最新 main**；如果 main 上出现了新的迁移，删除自己的迁移目录后重新生成，保证自己的迁移时间戳最新；
4. CI 的 `migrations` 任务会检查：迁移完整覆盖 schema（`prisma migrate diff --exit-code`），且能在空库上从头执行；
5. 已合并到 main 的迁移**不可修改**，只能追加新迁移；
6. 审计表 `audit_log` 的 UPDATE / DELETE 权限在数据库账号层面回收（运维脚本，见审计 issue）。

### 5. 种子数据

`apps/server/prisma/seed/<序号>-<域>.seed.ts`，默认导出 `async (prisma) => void`，必须幂等（upsert）。
序号决定执行顺序：`10-org`、`20-settings`、`30-consent`、`40-module-home`、`50-engine`、`60-assessment`……
种子中只允许虚构数据和文档附录中的配置（附录 A–H），**真实客户数据不得进入任何种子文件**。
